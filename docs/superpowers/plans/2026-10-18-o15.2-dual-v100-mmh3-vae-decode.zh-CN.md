# Raylight 1.18.0 / O15.2 双 V100 MiniMax H3 VideoVAE 并行解码实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改 ComfyUI 或 Director 的情况下，把 Director 的 MiniMax H3 VideoVAE 时间块分配给 GPU0 主进程与 GPU1 Ray worker 并行计算，并完成自动化、实机性能、质量、生命周期和回退验收。

**Architecture:** Raylight 在代理模型的 Director `execute` 生命周期内安装执行上下文和标准 `VAEDecode` 桥。rank 1在后台预载CPU VAE，采样结束后与GPU0各解一半时间块；主进程复现官方时间重叠融合与像素终结，并在不满足门禁或异常时调用原生解码。

**Tech Stack:** Windows、Python 3.12.10、PyTorch 2.12.0+cu126、ComfyUI、Ray 2.57.0、2×V100-SXM2-16GB TCC、pytest、xFormers。

**Spec:** `docs/superpowers/specs/2026-10-18-o15.2-dual-v100-mmh3-vae-decode-design.zh-CN.md`

## Global Constraints

- 唯一可编辑源码为 `E:\ComfyUI-py310\raylight-windows-v100-fsdp-p2p`；部署副本只能由提交后的部署脚本生成。
- 不修改 ComfyUI、MiniMaxH3Director、SOL Attention 或 TE-Speed 源码。
- 非Ray Director、单GPU、未知VAE和异常路径必须原生回退。
- 不改变采样FSDP/P2P、Refine参数、缓存键、音频或保存行为。
- 每项生产代码先有能正确失败的自动化测试。

## Review Focus

- 后台预载与下一段采样并发时不得让VAE驻留GPU或破坏扩散模型加载。
- Director异常退出后上下文必须清除，第二个工作流不得继承前一个actor或VAE。
- 乱序、缺块、重复块和非有限输出必须拒绝并原生回退。
- 末尾pad token和5帧重叠必须与官方107帧输出同形。
- Refine/FaceRefine多次调用标准 `VAEDecode` 时必须复用缓存而不增加worker。
