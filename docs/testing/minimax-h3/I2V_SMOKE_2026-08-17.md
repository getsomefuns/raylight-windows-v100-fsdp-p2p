# MiniMax H3 I2V Smoke Validation — 2026-08-17

## Validation goal

Prove that the Windows V100 branch can execute a complete MiniMax H3 I2V pipeline with the diffusion model sharded across two GPUs, CUDA collectives carried over the custom P2P/NVLink backend, and finite video/audio output.

## Test conditions

- Native Windows 23H2; two Tesla V100-SXM2-16GB in TCC mode; driver 577.00.
- Python 3.10.11; PyTorch 2.7.0+cu126; Ray 2.57.0; yunchang 0.6.4; comfy-kitchen 0.2.30; ComfyUI 0.31.0.
- FP8-scaled FL2VA diffusion model, NVFP4 Qwen3-VL text encoder, FP16 video VAE and FP32 audio VAE.
- FSDP enabled, Ulysses 2, synchronized Ulysses, TORCH_EFFICIENT attention, mmap enabled, CPU offload disabled.
- Reduced smoke workload: 448x448, 39 frames at 24 fps, 12 sampler steps.
- ComfyUI arguments: `--disable-cuda-malloc --reserve-vram 2`.

## Information observed

- Prompt validation and all required graph connections.
- Text-encoder load policy and temporary dequantization headroom.
- Both-rank initialization, FSDP registration and local shard payload.
- CUDA P2P health bandwidth and collective profile.
- GPU utilization, VRAM, host physical/committed memory and pagefile use.
- Rank-output equality, finite tensors, container streams and temporal variation.

The first attempt with the default VRAM reserve failed before Ray initialization: the unsharded 32B text encoder left only about 158 MiB free while an NVFP4 layer required a 500 MiB dequantization buffer. Reserving 2 GiB caused ComfyUI to keep about 2.1 GiB of text-encoder weights offloaded while still running text encoding on GPU, and the complete workflow then passed.

## Conclusion

The I2V smoke acceptance gate passes. This run proves real two-GPU FSDP participation and CUDA P2P/NVLink transport on native Windows, not a Gloo-host-memory fallback. The 2 GiB VRAM reserve is required for this V100/torch 2.7 text-encoder path. Host commit peak remains the main capacity risk for larger MiniMax workloads. The next validation target is reduced REF2VA, followed by the 0.4 MP I2V reference workload.

Raw logs, one-second telemetry and generated media remain local test artifacts and are intentionally not stored in the repository.
