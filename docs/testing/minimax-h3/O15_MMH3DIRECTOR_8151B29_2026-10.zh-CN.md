# O15 MiniMaxH3Director 8151b29 验收记录

## 1. 验证目标与环境

目标是在不修改 ComfyUI 和 Director 源码的条件下，把官方 Director 从 `576424f` 升级到 `8151b29`，保留现有 Raylight 双 V100 FSDP/P2P 能力，并让新版分段 LoRA 真实进入两个 worker 且不跨段污染。

- Windows，2× Tesla V100-SXM2-16GB，TCC，驱动 577.00，NVLink/CUDA P2P；
- Python 3.12.10，PyTorch 2.12.0+cu126，Ray 2.57.0，xFormers 0.0.35；
- Raylight 1.17.0 候选；Director 官方干净提交 `8151b29`；
- `P2PCapacityMiB=256`，`ReserveVramGiB=4`，`--disable-cuda-malloc`；
- 原始 JSON、日志和媒体探针位于本地 `.local/artifacts/o15/`，不提交长日志或生成视频。

## 2. 上游差异与适配判定

| 上游功能 | 是否跨越 Ray 代理边界 | 验证方式 | 结果 |
|---|---|---|---|
| Refine 画布/keyframe/cond 重对齐 | 是，仍调用 `sample_single_stage` | 真实 O14 SelfLift + Refine | 通过 |
| FL2V 选择运行、续接和尾帧修复 | 否，Director 主进程 | schema/接口回归 | 共存 |
| raw/FFV1 缓存 | 否 | 5×32×48 RGB uint8 FFV1 往返 | 像素完全一致 |
| 自定义缓存文件夹名 | 否 | `workflow-A_5`、`workflow-B_5`、`workflow-A_6` | 命名空间隔离 |
| 真实音频采样率 | 否 | 实机输出 ffprobe | AAC 32000 Hz |
| prefetch 清理 | 间接影响显存生命周期 | 两段实机连续完成 | 无 actor death/OOM |
| 分段 LoRA | 是，官方函数不能作用于无权重代理 | 描述符桥 + 双卡两段实机 | 通过 |

官方节点测试为 `2 passed, 10 subtests passed`；Director 工作树 HEAD 与 `origin/main` 均为 `8151b29` 且状态干净。节点 schema 确认 Director、Refine、SelfLift、FaceRefine、Semantic Bridge 全部注册，并包含 `cache_frames_codec`、`cache_name`、`export_pre_face_refine` 与 `images_pre_face_refine`。

| 双卡采样合计 | 143.83 s | 152.37 s | +5.94% |
| GPU 峰值 | 9351 / 9329 MiB | 9351 / 9329 MiB | 不变 |

三次采样全部为远程双 rank，未本地回退。输出 864×480、24 fps、124 帧、5.1667 秒；124/124 帧唯一。音频 AAC 双声道 32 kHz，NaN/Inf 为 0，DC、RMS 和 zero-crossing 与 O14 正常基线一致。

结论：功能与质量通过，显存未回退；本轮冷启动性能较旧记录下降，不能宣称新 Director 带来速度提升。

## 5. 自动化、P2P 与测试工具

- 最终全量测试：`769 passed, 219 warnings, 35 subtests passed`；警告来自既有 Torch 弃用、NestedTensor 原型提示和 Windows pytest 临时目录清理，没有测试失败。
- Director 兼容专项：96 tests + 2 subtests 通过；旧采样桥、SelfLift、Refine、preview、生命周期与 Safe-FP16 保持。
- Windows 硬件门禁：双卡 TCC，CUDA P2P correctness/dtype/tail/async 全通过，100 GiB 远端传输试验中位数约 61.4 GiB/s。
- 基准统计器不再用固定 2 秒窗口配对 actor 日志，而是按同 rank 最近一次准备起点归属；同时覆盖“前一次缺日志时后续 profile 不错位”的回归。

## 6. 结论与边界

O15 验收通过。Raylight 可以运行 Director `8151b29` 的原有首采、SelfLift 与同 checkpoint Refine，并正确消费新增分段 LoRA。分段 LoRA 只在当前 worker 临时克隆上生效，不累积到下一段。FFV1、自定义缓存名、音频采样率和段间清理可与代理共存，但它们是 Director 主进程功能，不是 Raylight 双卡加速项目。

选择运行/FL2V/FaceRefine 的每种组合没有在本阶段重新做完整长视频质量矩阵；其接口与注册门禁通过，既有 O13/O14 实机能力不撤销。未来 Director 如果改变 `sample_single_stage` 签名或绕开该入口，Raylight 会明确拒绝而不是静默本地执行。
