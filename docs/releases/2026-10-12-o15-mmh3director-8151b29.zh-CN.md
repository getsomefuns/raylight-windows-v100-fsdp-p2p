# Raylight 1.17.0：MiniMaxH3Director 8151b29 与分段 LoRA

## 升级范围

本版把经过验证的 MiniMaxH3Director 坐标从官方 `576424f` 更新到 `8151b291fcacee5ddb70c6493eaed4f831bc6867`。两者相差 25 个提交、32 个文件、3624 行新增与 332 行删除。Director 和 ComfyUI 源码均未修改；Raylight 只修改自己的 MODEL 代理、worker 请求协议、测试、基准工具、示例工作流和文档。

Director 升级后直接获得：

- Refine 在画布变化后重新对齐 keyframe、conditioning 与 PackedLayout；
- FL2V 选择运行、尾帧锁定与连续性修复；
- 分段像素帧可选 raw 或 FFV1 无损缓存；
- 自定义缓存文件夹名，并把节点 ID 加入目录键，降低工作流间缓存污染；
- 选择运行分段导出的单帧占位修复；
- 解码音频保留真实采样率；
- 分段清理时释放 ComfyUI prefetch 队列；
- 公共参数、混合模式、分段 LoRA 和前端交互更新。

这些是 Director 主进程能力，Raylight 不把它们宣称为双卡加速。Raylight 需要新增适配的关键项是分段 LoRA。

## Raylight 分段 LoRA 适配

官方实现对每个片段调用 `ModelPatcher.clone() + add_patches()`。Raylight 主进程中的 `Ray MODEL Adapter` 是无权重代理，不能直接加载或修改 Diffusion 权重。1.17.0 改为：

1. 主进程只解析 Director 的 active、非零 LoRA 行，校验 `models/loras` 路径与强度，最多保留 8 个；
2. LoRA 描述符随当前首采、SelfLift 或 Refine 请求发送给两个 Ray worker；
3. 每个 worker 在 SigmaShift 临时克隆之后、SOL/TE patch 重放之前应用当前片段 LoRA；
4. 全局 `RayLoraLoader` 仍是基础栈，分段 LoRA 只在本次临时采样模型上叠加；
5. 空栈或不同栈的下一片段从基础模型重新开始，不继承上一片段补丁；
6. 每个 worker 最多缓存最近两份 CPU LoRA state dict，并在模型切换、worker kill 或 LoRA 列表变化时清空。

普通 ComfyUI MODEL 仍调用 Director 官方实现；只有精确的 Ray 代理类型进入描述符桥。远端失败继续 fail closed，不会静默退回 GPU0。

## 实机结果

### 原 O14 完整工作流回归

固定 REF2VA、864×480、124 帧、24 fps、Turbo4、SOL、SelfLift 与 Refine 2 步，在新 Director 上完成三次双 rank 远程采样：

- 端到端 337.52 秒，采样合计 152.37 秒；
- GPU0/GPU1 峰值 9351/9329 MiB；
- 物理内存峰值 64925.77 MiB，Commit 峰值 113409.72 MiB，pagefile used 为 0；
- 输出 124/124 帧哈希唯一，音频可解码且 NaN/Inf 为 0；
- 相比 O14 已发布冷启动记录，采样慢 5.94%，端到端慢 16.97%。这只是两次独立冷启动观测，不归因于单个上游提交，也不宣称性能提升。

### 两段分段 LoRA 回归

示例工作流 `example_workflows/o15/MMH3Director_O15_SegmentLoRA_TwoSegment_Smoke.json` 保留全局 REF2VA Turbo4；第一段额外应用人物改善 LoRA 0.6，第二段为空栈。诊断运行使用 1 步，以验证路由和隔离而非评估画质：

- 两段分别触发一次远程双 rank operation，并复用同一对 worker；
- 第一段 104 个分段 LoRA patch 在两个 rank 各加载一次；第二段没有再次加载，报告也只在第一段列出 LoRA；
- 端到端 205.67 秒，双卡采样合计 53.79 秒；
- GPU0/GPU1 峰值 9431/9407 MiB；物理内存峰值 71045.47 MiB，Commit 峰值 117168.31 MiB，pagefile used 为 0；
- 输出 H.264 864×480、24 fps、146 帧、6.0833 秒；146/146 帧唯一；AAC 32 kHz 双声道可解码。

Director 把输入的 62+62 帧按模型规则对齐为 73+73 帧，这是官方时间轴规划结果，不是 Raylight 重复采样。

## 额外修复

多段实机测试暴露出基准统计器的日志配对错误：Ray 分别转发两个 actor 的 stdout，同一次 operation 的两个 profile 行可相差超过 2 秒。旧统计器按固定时间窗分组，会把一次操作误算成两次。现在把 profile 锚定到同一 rank 最近一次采样准备起点；缺失一条被 Ray 日志层去重的 peer 行时仍可保留该 operation，其准备阶段继续要求两个 rank 完整出现。

## 能力边界

- Director `8151b29`、旧版桥、SelfLift、同 checkpoint Refine、FaceRefine 接口、Semantic Bridge、SOL、TE、实时预览和连续分段均保留。
- 分段 LoRA 只作用于 Diffusion Model。Text Encoder LoRA、VAE LoRA 和更换 checkpoint 的自定义 Refine 不在本次保证内。
- raw/FFV1、自定义缓存目录、选择运行导出、音频采样率和 prefetch 清理仍由 Director 主进程负责；Raylight 只保证与远程采样共存。
- 本地保留 `576424f` Git bundle 作为回退证据；它位于忽略目录 `.local/backups/director/`，不提交仓库。
