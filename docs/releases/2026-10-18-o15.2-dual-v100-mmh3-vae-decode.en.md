# Raylight 1.18.0: Dual-V100 MiniMax H3 VideoVAE Decode

## Goal

O15.2 addresses the Director post-sampling VideoVAE stage that previously ran primarily on GPU0 and took about 66 seconds for 107 frames at 1920x1088. Only Raylight changes; ComfyUI, MiniMaxH3Director, SOL, and TE-Speed remain untouched.

## Shipped implementation

- Intercept standard `VAEDecode` only inside a Ray MODEL proxy Director `execute` scope.
- Preload the same VideoVAE on rank 1 CPU, then decode even temporal chunks on main-process GPU0 and odd chunks on worker GPU1.
- Preserve official temporal padding, five-frame overlap merge, crop, and IMAGE layout; reject missing, duplicate, malformed, or non-finite results.
- Reuse the VAE for repeated standard decodes in one Director execution and release GPU1 VAE memory before the next diffusion sample.
- Invoke original decode for single-GPU, non-proxy, unknown-VAE, or failing paths.
- Keep rank-1-only auxiliary VAE load outside the two-rank diffusion model budget collective without changing FSDP synchronization.
- Add official-native-versus-dual quality/resource benchmarking and automated gates.

## Results

Official single-GPU decode is 66.734 seconds. Five dual runs are 42.066, 40.117, 40.660, 39.885, and 40.508 seconds. Warm speedup is `1.647x` or `39.30%` lower time; GPU peaks are 6993/6513 MiB and utilization reaches 99%/100%. Dual output is element-exact to official output and all quality, performance, resource, and lifecycle gates pass.

The two-segment Director hardware regression decodes in 9.723/9.282 seconds and produces a valid 864x480, 24 fps, 146-frame, 6.083-second MP4. Both sampling operations use two ranks, the VAE-to-next-segment transition succeeds, and no process remains afterward.

The full automated suite reports `797 passed, 235 warnings, 35 subtests passed`; the complete O15.2 Python change set passes Ruff. Independent-review findings for fallback traceback retention, CPU preload-cache cleanup, and per-run quality gating are fixed and covered by regression tests.

See the [O15.2 English test record](../testing/minimax-h3/O15_2_DUAL_V100_VAE_DECODE_2026-10.en.md) for conditions, resource data, and rejected attempts.

## Boundaries

This is VideoVAE temporal parallelism, not VAE FSDP. AudioVAE is unchanged. Direct internal SelfLift `vae.decode()` is outside the 1.18.0 interception path, while standard-node primary and Refine/FaceRefine decode can use it. Existing explicit Ray samplers, LTX, legacy Director, FSDP/P2P, live preview, SOL/TE, and cache behavior remain compatible.
