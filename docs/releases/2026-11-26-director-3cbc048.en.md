# Raylight 1.19.1: MiniMax H3 Director compatibility update

[简体中文](2026-11-26-director-3cbc048.zh-CN.md)

This release does not change Raylight's dual-GPU sampler, FSDP/P2P, TP2, VAE, or RelayVSR runtime logic. The environment remains ComfyUI 0.46.0, Python 3.12.10, PyTorch 2.12.0+cu126, and two V100s in TCC mode. The verified production workflows require no rewiring or new launch arguments.

## Changes

- [Director #284](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/pull/284): SelfLift's continuation + redraw path now crops and pads the video denoise mask with each spatial tile. Both Ray workers use this implementation directly. A separate overlay restores full-frame masks, shapes, and conditions before fallback if tile layout setup fails. The full-frame fallback remains subject to available VRAM.
- [Director #287](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/pull/287): pre-decode DiT cleanup is opt-in. Older workflows restore missing values to off; explicitly saved settings are preserved. The switch applies to DiT in the ComfyUI process, not remote Ray workers, and is not a dual-GPU VAE speed toggle.
- [Director #285](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/pull/285): new segment MP4s are one-based. Running only segment 2 still produces `seg_0002.mp4`. Cache slots remain zero-based; existing cache files and exports are not renamed.
- The local PR231 metadata-only cache checks and frontend cancellation/deduplication are retained, as are the unpublished export-tail and face-tracking fixes (initial left/right face selection and tracking reach). The [four overlays](../../patches/director/README.md) can be replayed from a clean upstream checkout without changing ComfyUI or reinstalling dependencies.

## Isolated hardware acceptance

All cases used four steps and seed 42. SelfLift used two low-resolution and two high-resolution steps.

| Workflow | Output | End to end | Stage times |
|---|---|---:|---|
| Two-segment R2V/SelfLift, cleanup on | 864×480, 24 fps, 39 + 51 frames | 548.0 s | Conditioning 128.5 s; sampling 305.1 s; decode 18.5 s |
| Same inputs and seed, cleanup off | Same | 438.7 s | Conditioning 84.5 s; sampling 267.1 s; decode 18.0 s |
| Regenerate only segment 2 | 864×480, 24 fps, 51 frames | 216.1 s | Only `seg_0002.mp4` exported |
| Existing workflow, no VSR | 864×480, 24 fps, 124 frames | 239.6 s | Conditioning 51.1 s; sampling 161.4 s; decode 16.8 s |
| Director with dual-V100 RelayVSR 2× | 1728×960, 24 fps, 56 frames | 239.4 s | Conditioning 52.3 s; sampling 101.9 s; source decode 10.2 s; VSR 49.9 s including 34.1 s for two-worker Flash decode |

The on/off runs produced identical decoded video and audio, and each completed four dual-rank sampling operations. Sampled board peaks were 9303/9281 MiB on and 9373/9351 MiB off; total system RAM peaked at about 71.1 and 71.0 GiB respectively. The main-process check took about 0.4 s per segment and freed 0.00 GiB when enabled. The independent starts differed in conditioning, sampling, and startup times, so the timing gap is not attributed to the switch or claimed as a speedup. Rank traces, fault-injected fallback, cache-status, and face-tracking checks passed; a full production series was not re-rendered for quality comparison.

## Production regression

| Matched workflow | 1.19.0 → 1.19.1 end to end | 1.19.1 conditioning / sampling / decode | 1.19.1 GPU0 / GPU1 peak; system RAM peak |
|---|---:|---|---|
| No VSR, cold start, 124 frames at 864×480 | 353.2 → 294.4 s | 39.7 / 178.4 / 15.3 s | 9223 / 9201 MiB; 71.5 GiB |
| RelayVSR 2×, warm workers, 56 frames at 1728×960 | 208.9 → 197.0 s | 38.0 / 99.7 / 9.0 s; VSR 37.9 s (26.8 s two-worker Flash) | 9247 / 9225 MiB; 63.6 GiB |

Both production outputs were 24 fps and passed full video/audio decoding checks. The old and new measurements are single runs including load and system-cache effects, not a promised speedup. The full regression passed 965 tests and 35 subtests; five frontend tests passed. The production deployment was checked and test-owned processes stopped.

## Use and rollback

Use the existing launcher. Restart ComfyUI and hard-refresh the frontend after updating. Keep the old Director branch when moving the upstream base from `aff2579` to `3cbc048`; do not overwrite the patched node with Manager. The preserved Director `LOCAL_PATCHES.md` is a historical record; follow these release notes for the current setup. To roll back, finish the queue, stop ComfyUI, and restore the previous Director branch and Raylight `v1.19.0` deployment. There is no need to remove workflow or cache data.

No test videos, new test cases, fixture workflows, or raw logs are included in this release. See the [plan](../superpowers/plans/2026-11-26-director-3cbc048.md) for scope and acceptance gates.
